# Uso de IA en MiTeVe-API

> Prompts útiles para tareas con IA en este repo (Kotlin + Spring Boot).

---

## Cómo usar estos prompts

1. Copia el bloque del prompt.
2. Reemplaza `[CORCHETES]` por tu caso real.
3. Pégalo en tu agente IA (recomendado: **OpenCode**).
4. Revisa antes de commitear: la IA propone, tú decides.

---

## 1. Corregir errores de build en bucle

```text
Revisa los errores que está dando ./gradlew build. Cuando los arregles, genera un build nuevo para volver a verificar y así sucesivamente hasta que ya no haya errores ni warnings.
```

---

## 2. Agregar endpoint siguiendo las capas

```text
Agrega el endpoint [MÉTODO new-api/ruta] en [ContentController/EpisodeController/...] siguiendo las capas controllers → services → repositories → entities + mappers/dtos. Usa MapStruct en mappers/ y errores tipados de errors/ (NoExists/BadRequest). Guíate del método findById en controllers/ContentController.kt.
```

Ejemplo:

```text
Agrega el endpoint GET new-api/seasons/top en SeasonController siguiendo las capas controllers → services → repositories → entities + mappers/dtos. Guíate de findTopWatched en controllers/ContentController.kt.
```

---

## 3. Mover lógica a su capa (responsabilidad única)

```text
Verifica las funciones de [services/X] para ver si pertenecen a ese archivo/capa o a otra. Si hay una query de [EntidadA] en el servicio de [EntidadB] sin necesidad de [EntidadB], muévela a su service/repository/mapper correcto. La regla es controllers → services → repositories → entities.
```

---

## 4. Estandarizar archivo Kotlin (ktfmt + capas)

```text
Arregla [archivo.kt] para que siga kotlin-format (ktfmt, imports, naming) y las reglas de 08-code-style.md: controller delega al service, MapStruct para DTOs, errores vía ErrorHandler, sin SQL en services. Al final corre ./gradlew build y corrige hasta que pase.
```

---

## 5. Generar notas de release estilo GitHub

```text
Obtén unas notas de release como lo hace GitHub en "Generate release notes", tomando como inicio el último tag [vX.Y.Z] y como final lo actual de develop.
```

---

## 6. Revisar seguridad antes del PR

```text
Revisa [Security.kt/SecurityConfig.kt o mi rama] y dime si rompo algo: perfiles init/!init, filtros JwtAuthenticationFilter/JwtAuthorizationFilter, CORS (localhost:3000, miteve.vercel.app), LoggedUser. No propongas secretos hardcodeados.
```

---

## Reglas al pedirle a la IA

- Una tarea a la vez (no mezclar endpoint + migración + release).
- Mencionar siempre el archivo guía (`ContentController.kt`, `SecurityConfig.kt`, `08-code-style.md`).
- Si el primer resultado es parcial, iterar con refuerzo en vez de empezar de cero.
- Verificar `./gradlew build` antes de commitear.
